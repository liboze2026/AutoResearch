# Stage3 Known Limitations

## 总体说明

阶段3已经完成“受控智能体期”的最小目标，但当前系统仍然有清晰边界。

这些限制是当前设计边界，不应误判为阶段3未完成：

- 当前仍是受控智能体，不是完全自治科研系统
- 当前重点是统一 runtime、结构化输出、可校验、可修复、可持久化
- 当前真实模型与真实抓取能力只保留受控扩展点，不默认开放

## 1. 不是完全自治科研闭环

当前系统不支持：

- 长周期自主科研循环
- 无人值守的目标重写与计划重写
- 自由聊天式多智能体协商系统
- 无边界的自动联网研究

这意味着：

- 阶段3证明的是“受控 agent pipeline 成立”
- 不是“完全自治科研系统已经成立”

## 2. `Writer / Picture` 仍是最小版本

当前状态：

- `Writer` 已经能够生成结构化 draft
- `Picture` 仍并入 `Writer` 的最小实现
- 当前 picture 能力仍是 mock 路径

当前不支持：

- 独立的真实 `Picture Agent`
- 复杂图表生成编排
- 多模态图文联动生成闭环

这意味着：

- 阶段3已经有可归档的写作末端
- 但仍不是完整论文生产系统

## 3. `Coding` 仍限制在统一训练模板中

当前状态：

- `Coding + Evaluator` 已作为受控节点实现
- 生成内容受统一训练模板约束
- 输出仍回到阶段2的 `ExperimentSpec / ExperimentRun / ResultArchive / ResultComparison`

当前不支持：

- 无约束自由代码生成后直接执行
- 脱离模板的任意训练系统编排
- 任意环境下的自动代码修改与自主实验闭环

这意味着：

- 阶段3强调“可审计、可回放、可复用”
- 而不是“无限制代码自治执行”

## 4. 真实模型 API 仍是受控扩展点

当前状态：

- runtime 已保留 `api` mode
- 已支持 `AGENT_API_*` 配置入口
- 默认不启用 live execution

当前不支持：

- 默认接通真实线上模型
- 无显式授权的真实 key 自动读取与调用
- 绕过统一 contract 的自由模型调用

这意味着：

- 阶段3已经把真实 API 接入位留出来了
- 但真实接入仍属于后续受控扩展工作

## 5. 真实抓取与真实检索能力仍是受控扩展点

当前状态：

- Reader、Dataset 等节点已经可以跑受控最小链路
- 系统优先复用 MRAG 现有数据集扫描、科研资产、服务器/GPU 探测能力

当前不支持：

- 自由网页抓取
- 无约束外网检索
- 任意来源数据的自动采集与自动清洗闭环

这意味着：

- 阶段3强调“受控输入源”
- 而不是“开放抓取式研究代理”

## 6. `codex_cli` 仍以最小联调和验收为主

当前状态：

- `codex_cli` 是当前最小测试优先模式
- 不可用时会稳定回退到 `mock`
- 回退信息会进入 warnings、job、artifact、summary

当前不支持：

- 把 Codex CLI 当作完全可靠的生产执行面
- 无日志、无结构化输出的直接 CLI 使用

这意味着：

- 阶段3证明的是 runtime 对 `codex_cli` 的受控适配
- 而不是对任何 CLI 工具的无约束接入

## 7. 自动流水线仍是最小编排版本

当前状态：

- 已有最小 event-driven pipeline
- 已有默认 subscription：
  - `paper_parsed -> insight`
  - `insights_ready -> idea_generator`
  - `idea_ready -> planner`
  - `plan_ready -> coding`

当前不支持：

- 复杂 DAG 图形编排器
- 高级冲突解决与优先级系统
- 大规模多租户分布式 agent worker 平台

这意味着：

- 阶段3已经有最小自动流水线
- 但仍不是完整自治 orchestration 平台

## 8. 并发与恢复仍保持保守策略

当前状态：

- 支持受控并发与重试
- 验收脚本会验证失败定位、log、fallback、summary

当前不支持：

- 大规模分布式 lease/抢占系统
- 复杂 backoff / queue fairness / 全局调度策略
- 完整 checkpoint resume 式 agent 恢复

这意味着：

- 阶段3已经满足“可跑、可复跑、可定位”
- 但尚未进入更复杂的阶段4执行编排层

## 9. `shenzhenvlab` 真实链路依赖真实环境

当前状态：

- 如果 `shenzhenvlab` 记录存在且 GPU 空闲，可走最小真实路径
- 否则自动回退 mock

当前限制：

- 如果验证数据库中不存在该记录，probe 会显示 `missing`
- 自动验收不会主动创建或伪造真实服务器记录

这意味着：

- 阶段3遵守“保留真实记录、不可误删、可自动回退”的边界
- 真实服务器版验收需要真实数据库环境配合

## 结论

阶段3当前可概括为：

- 受控智能体系统已经成立
- 自动验收与端到端链路已经成立
- 关键边界仍然清晰保守

阶段4如果继续扩展，应该在这些边界上做增强，而不是回退成自由聊天式科研代理。
