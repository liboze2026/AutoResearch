# Stage2 Known Limitations

## 总体说明

阶段2当前已经完成最小实验自动化闭环，但它仍然是“稳定跑通基础设施”的版本，而不是完整科研智能系统。

以下限制是当前设计边界，不应误判为阶段2未完成。

## 1. 统一训练模板仍是最小版本

- 当前稳定模板是 `mock_train_template`
- `train.py / evaluate.py / runner.py` 已保留真实训练扩展点
- 但当前并未接入复杂深度学习框架或多模板生产系统

这意味着：

- 阶段2证明的是模板化执行底座已接通
- 不是已经完成完整训练平台

## 2. 恢复机制仍是最小重试版本

- 当前支持失败信息沉淀
- 当前支持 recovery 视图
- 当前支持 retry 创建新 run 并重新进入 `queued`

但当前不支持：

- checkpoint resume
- 跨服务器断点续跑
- 自动迁移中间产物
- 复杂故障分类编排

这意味着：

- 阶段2已经具备最小恢复能力
- 但还不是完整容错执行系统

## 3. 结果对比还不是自动科研决策器

- 当前 comparison 会做最小指标逐项对比
- 当前会生成 `summary_md`
- 当前可对比 baseline 和同 dataset asset 下历史 result archive

但当前不支持：

- 自动 SOTA 判断
- 复杂统计显著性分析
- 自动科研建议生成
- 自动实验淘汰与研究路线规划

这意味着：

- 阶段2的 comparison 是“结构化结果对比”
- 不是“自动科研决策引擎”

## 4. 调度器是最小规则版

- 当前只基于 heartbeat、GPU snapshot、空闲显存、utilization、粗粒度队列长度做选择
- 当前明确复用已有资源数据，不重新探测

但当前不支持：

- 复杂资源约束建模
- 模型大小估算驱动调度
- 多 GPU / 多机任务编排
- 更复杂的优先级与公平性策略

## 5. 日志系统是最小可查版本

- 当前可记录 stdout / stderr
- 当前可查看日志 tail
- 当前可在失败时保留最后日志摘要

但当前不支持：

- 实时流式日志订阅
- 大规模日志检索
- 复杂日志聚合与分析

## 6. 远程执行仍是最小闭环

- 当前复用了 MRAG 已有 SSH / 远程执行能力
- 当前可准备远程目录、下发文件、启动模板 runner、回收产物

但当前不支持：

- 大规模工件分发优化
- 高吞吐批量远程作业系统
- 分布式训练编排

## 7. 前端页面仍以验收闭环优先

- 当前已具备实验列表、实验详情、运行详情区域、结果对比页、服务器资源增强页
- 当前具备 loading / error / empty 的最小状态

但当前不支持：

- 复杂筛选与批量操作
- 更强的历史 run 时间线
- 深度可视化分析

## 8. 环境层已知噪声

当前验收已通过，但环境中仍有几类非阻塞噪声：

- WSL 下 `localhost / NAT` 警告输出
- Docker 的 `USERPROFILE` warning
- 前端构建 chunk size warning

这些问题不会阻塞阶段2验收，但会影响输出整洁度。

## 为阶段3预留的扩展点

阶段3应直接沿这些点扩展，而不是推翻阶段2：

- 在统一模板系统上增加真实训练模板
- 在 experiment spec 生成链路上接入 planner / coding agent
- 在 recovery 之上增加更强的恢复策略
- 在 result comparison 之上增加更强的科研分析能力

## 结论

阶段2当前状态可以概括为：

- 已完成最小实验自动化闭环
- 已完成最小恢复与最小对比
- 未进入阶段3的智能规划与科研决策
